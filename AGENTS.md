# Project direction

New CAD functionality should be native to AirCAD. FreeCAD is no longer part of the intended project workflow; do not add FreeCAD integration or make new features depend on it. Existing legacy integration files should not be removed without an explicit request.

# Frontend verification

Run these from `web/` before handing off frontend changes:

- `npm test` — Vitest unit suite.
- `npm run build` — typecheck plus the production Vite build.
- `npm run test:ui` — Playwright browser tests. Requires `npm exec -- playwright install chromium` once per machine.

The browser tests mock `/api/tracker` and `/ws`, so no Python server or camera is needed. Review screenshots land in `web/test-results/review/` (regenerated each `test:ui` run — Playwright wipes `test-results` first).

## Voice prototype

- Voice in `web/src/voice/` is a separate measurement input for active native line and face-pull sessions. It supplies a positive distance only; sessions own target/direction. No idle selected-object fallback or FreeCAD routing.
- Two recognizers sit behind one panel and one V key, chosen by the `Recognizer` select in the voice panel. `browser` is the default and the main path; `qwen` is the opt-in alternative. The choice lives in `web/src/voice/engine.ts` and persists in `localStorage` under `aircad.voice.engine`, falling back to `browser` when the value is missing, unknown, or storage is blocked. Do not make `qwen` the default and do not delete it.
- The `browser` recognizer uses the Speech Recognition API (`SpeechRecognition` / `webkitSpeechRecognition`) in Chrome or Edge on localhost or HTTPS. The browser streams a transcript; AirCAD parses a positive distance locally and never sends audio to Python or Yibu. Firefox and other browsers without that API fail immediately with a panel error. Credentials and `VITE_*` variables are not used on this path.
- The `qwen` recognizer records WAV audio in `web/src/voice/microphone.ts` and posts it to `/api/voice/command`. `voice_api.py` follows the organizer's `yibuapi_examples_20260918_v01` HTTP contract: `https://yibuapi.com/v1/chat/completions`, model `qwen3.5-omni-flash`, Bearer `YIBU_API_KEY`, and WAV data-URL `input_audio`. Credentials come only from the Python server environment; `.env` files are not loaded automatically and keys must never use `VITE_*` variables.
- `yibu_audit.py` is the unchanged organizer helper. Each upstream attempt records purpose `aircad_voice_resize_axis` and actual usage in `artifacts/yibu_api_calls.jsonl` (override with `YIBU_AUDIT_LOG`). Missing usage remains null. Do not log keys, prompts, or audio to this ledger, and do not silently bypass audit failures.
- The voice HTTPS request explicitly uses the certifi CA bundle with certificate and hostname verification enabled. Some macOS Python installations have no default CA bundle; do not work around that by disabling TLS verification.
- Lines use a continuously refined free-angle voice guide from the last 12 movement-filtered drag samples after 32 screen pixels, within the active XY/XZ/YZ work plane at its actual 3D offset. Automatic grid/near-axis snaps do not quantize this guide; explicit X/Y/Z locks and on-plane object constraints are honored. V freezes the displayed direction; normal non-voice shape recognition stays unchanged. Face pulls use the current grab's baseline and the selected face's normal/sign, preserving the opposite face/orientation/extrusion sign for solids.
- V during a draw/pull captures and freezes the draft before the recognizer opens. On `browser`, a transcript that full-matches a distance **with units** commits immediately (interim or final), and bare numbers wait for a final result or a second V. On `qwen`, V again stops recording and sends. Either way the user may release while the recognizer is open, valid results replace the rough distance and immediately commit one undoable edit, and Esc cancels the draft/request. Normal non-voice release-to-commit is unchanged. The recognizer select is locked while a request is in flight.
- A failed or cancelled attempt clears the frozen draft instead of holding it for retry: the rough gesture follows the cursor again and the normal release commits it. Retrying means re-capturing on the live draft, not resuming the old one. This matters because a pending draft blocks every action except voice and cancel, and the pen remote has no cancel key — do not restore retry-on-the-frozen-draft without also giving every input a way out.
- The command applied to CAD is `{distance_mm: number}`; context is `{operation: 'line'|'face_pull', units: 'mm'}`. Validate positive finite limits, exact geometry (no grid rounding/clamping), and stale operation identity/revision. Browser transcripts may contain number words; fold those to digits, then full-match a bare distance or 'by' distance. API transcripts write spoken numbers as digits and must full-match the same forms. Legacy axis instructions are rejected; audit purpose stays `aircad_voice_resize_axis` for compatibility.
- Focused checks: `.venv/bin/python -m unittest discover -s tests -p 'test_voice*.py' -v`; from `web`, `npm test -- src/voice/transcript.test.ts src/voice/speech.test.ts src/voice/engine.test.ts src/voice/microphone.test.ts src/voice/control.test.ts src/voice/commands.test.ts src/main.test.ts src/model/commands.test.ts src/model/stroke.test.ts src/model/extrusion.test.ts src/model/faces.test.ts src/input/input.test.ts` and `npm run build`.

## Pen remote

- The four-button BLE remote is a dumb transport. `firmware/smart_pen_remote/smart_pen_remote.ino` reports button 1-4 press/release as `F17`-`F20` and nothing else; every mode, threshold, chord and action lives in `web/src/input/remote.ts`. Do not move mode or timing logic into the firmware: the HUD needs the mode, the thresholds get tuned without reflashing, and the app calls `undo` directly rather than synthesizing a per-OS `Ctrl`/`Cmd+Z`.
- `F17`-`F20` are used because AirCAD already binds 1/2/3 to view presets and because those keys are unprintable, so a button can never type into the measure dialog or the inspector. Do not move down to `F13`-`F16`: macOS assigns F13 to Print Screen and F14/F15 to brightness, so those fire system actions instead of reaching the browser. Do not go past `F20` either — F21+ have no macOS virtual key code, so the browser reports no usable `code`. `REMOTE_BUTTON_CODES` is the single source with the reverse map derived from it; keep it in step with `buttonKeys` in the firmware.
- Hardware is a classic ESP32 (WROOM) with buttons soldered to GPIO 0, 1, 3, 4. Those are awkward pins and the consequences are not negotiable: keep `DEBUG_SERIAL` at 0, because `Serial.begin()` claims GPIO1 (UART0 TX) and silently kills button 2, and run the board on charger/battery power rather than a USB data cable, because the USB-serial bridge drives the GPIO0 auto-reset circuit. Rewiring to GPIO 5, 18, 19, 4 removes both constraints; only then enable the serial logs. Avoid GPIO 2/12/15 (strapping), 6-11 (SPI flash) and 34-39 (no internal pull-up, so `INPUT_PULLUP` does nothing).
- The buttons are not the pointer: keycap CV tracking supplies the cursor, and button 1 is the only grab now that pinch detection is gone (`gripping` is just `held.has('draw')`).
- Gestures: button 1 hold draws/orbits/pans by mode and is the drag grab during a push/pull, move or scale; button 1 tap selects and two taps undo; button 2 tap cycles mode; button 3 tap sends `Tab` and holding it records voice until release; button 4 tap opens a push/pull and applies on the next tap, holding it moves and releasing applies; 2+4 fits the view; 2+3 releases everything.
- A tap discards the gesture it opened before the hold is released, because releasing `draw` commits and a hand-held tip drifts well past `MIN_STROKE_PX`. Taps only carry select/undo in draw mode. Mode never changes mid-gesture.
- Button 2 acts on release so a chord can pre-empt it, and is a modifier while held. 2+4 is limited to `chordMs` (shorter than `holdMs`, so a fit never interrupts a move that already started); 2+3 is exempt from that window and from the resolved-hold guard, and takes precedence — the safety gesture has to work while something is already running.
- `RemoteSource` is driven by `down`/`up` plus a per-frame `tick` off `performance.now()`, with no timers, so it stays deterministic under test. `reset()` on focus loss forgets held buttons and unwinds anything live, but keeps the chosen mode.
- The remote is handled before the docked-chrome check and pulls focus back to the viewport, so a stray click in a panel cannot leave it dead. It yields to the measure dialog so a button cannot interrupt typing.
- `window.aircad.remote()` reports the mode and the last code seen, and unmapped function keys flash on screen; both exist for pairing a new remote. `window.aircad.remoteButton()` drives buttons without hardware.
- Focused checks: from `web`, `npm test -- src/input/remote.test.ts src/main.test.ts` and `npm run build`.

## Closed-outline extrusion

- Native profiles are any simple closed planar outline: polygons (`PolygonEntity`), rectangles, and virtual `LineLoopProfile`s detected from endpoint-connected lines. Virtual loops are never serialized; extruding one consumes only its unshared source lines as a single undoable edit.
- Shared polygon geometry lives in `web/src/model/polygon.ts` (planarity, simple-ring validation, `ShapeUtils.triangulateShape` triangulation) and loop detection in `web/src/model/loops.ts`; keep them free of runtime import cycles.
- Circle fitting/drawing was removed: round closed strokes square up to rectangles. Legacy saved circles still load, render, and serialize, but are read-only (no extrude/diameter edit) — do not reintroduce a circle command without an explicit request.
- Out of scope: holes, non-planar or self-crossing outlines. Do not silently clamp or grid-round typed/voice measurements.
