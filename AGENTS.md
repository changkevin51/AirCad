# Project direction

New CAD functionality should be native to AirCAD. FreeCAD is no longer part of the intended project workflow; do not add FreeCAD integration or make new features depend on it. Existing legacy integration files should not be removed without an explicit request.

## Voice prototype

- Voice in `web/src/voice/` is a separate measurement input for active native line and face-pull sessions. It supplies a positive distance only; sessions own target/direction. No idle selected-object fallback or FreeCAD routing.
- Two recognizers sit behind one panel and one V key, chosen by the `Recognizer` select in the voice panel. `browser` is the default and the main path; `qwen` is the opt-in alternative. The choice lives in `web/src/voice/engine.ts` and persists in `localStorage` under `aircad.voice.engine`, falling back to `browser` when the value is missing, unknown, or storage is blocked. Do not make `qwen` the default and do not delete it.
- The `browser` recognizer uses the Speech Recognition API (`SpeechRecognition` / `webkitSpeechRecognition`) in Chrome or Edge on localhost or HTTPS. The browser streams a transcript; AirCAD parses a positive distance locally and never sends audio to Python or Yibu. Firefox and other browsers without that API fail immediately with a panel error. Credentials and `VITE_*` variables are not used on this path.
- The `qwen` recognizer records WAV audio in `web/src/voice/microphone.ts` and posts it to `/api/voice/command`. `voice_api.py` follows the organizer's `yibuapi_examples_20260918_v01` HTTP contract: `https://yibuapi.com/v1/chat/completions`, model `qwen3.5-omni-flash`, Bearer `YIBU_API_KEY`, and WAV data-URL `input_audio`. Credentials come only from the Python server environment; `.env` files are not loaded automatically and keys must never use `VITE_*` variables.
- `yibu_audit.py` is the unchanged organizer helper. Each upstream attempt records purpose `aircad_voice_resize_axis` and actual usage in `artifacts/yibu_api_calls.jsonl` (override with `YIBU_AUDIT_LOG`). Missing usage remains null. Do not log keys, prompts, or audio to this ledger, and do not silently bypass audit failures.
- The voice HTTPS request explicitly uses the certifi CA bundle with certificate and hostname verification enabled. Some macOS Python installations have no default CA bundle; do not work around that by disabling TLS verification.
- Lines use a continuously refined free-angle voice guide from the last 12 movement-filtered drag samples after 32 screen pixels, within the active XY/XZ/YZ work plane at its actual 3D offset. Automatic grid/near-axis snaps do not quantize this guide; explicit X/Y/Z locks and on-plane object constraints are honored. V freezes the displayed direction; normal non-voice shape recognition stays unchanged. Face pulls use the current grab's baseline and the selected face's normal/sign, preserving the opposite face/orientation/extrusion sign for solids.
- V during a draw/pull captures and freezes the draft before the recognizer opens. On `browser`, a transcript that full-matches a distance **with units** commits immediately (interim or final), and bare numbers wait for a final result or a second V. On `qwen`, V again stops recording and sends. Either way the user may release while the recognizer is open, valid results replace the rough distance and immediately commit one undoable edit, and Esc cancels the draft/request. A failed or cancelled request can be retried on the frozen draft. Normal non-voice release-to-commit is unchanged. The recognizer select is locked while a request is in flight.
- The command applied to CAD is `{distance_mm: number}`; context is `{operation: 'line'|'face_pull', units: 'mm'}`. Validate positive finite limits, exact geometry (no grid rounding/clamping), and stale operation identity/revision. Browser transcripts may contain number words; fold those to digits, then full-match a bare distance or 'by' distance. API transcripts write spoken numbers as digits and must full-match the same forms. Legacy axis instructions are rejected; audit purpose stays `aircad_voice_resize_axis` for compatibility.
- Focused checks: `.venv/bin/python -m unittest discover -s tests -p 'test_voice*.py' -v`; from `web`, `npm test -- src/voice/transcript.test.ts src/voice/speech.test.ts src/voice/engine.test.ts src/voice/microphone.test.ts src/voice/control.test.ts src/voice/commands.test.ts src/main.test.ts src/model/commands.test.ts src/model/stroke.test.ts src/model/extrusion.test.ts src/model/faces.test.ts src/input/input.test.ts` and `npm run build`.

## Closed-outline extrusion

- Native profiles are any simple closed planar outline: polygons (`PolygonEntity`), rectangles, and virtual `LineLoopProfile`s detected from endpoint-connected lines. Virtual loops are never serialized; extruding one consumes only its unshared source lines as a single undoable edit.
- Shared polygon geometry lives in `web/src/model/polygon.ts` (planarity, simple-ring validation, `ShapeUtils.triangulateShape` triangulation) and loop detection in `web/src/model/loops.ts`; keep them free of runtime import cycles.
- Circle fitting/drawing was removed: round closed strokes become polygons. Legacy saved circles still load, render, and serialize, but are read-only (no extrude/diameter edit) — do not reintroduce a circle command without an explicit request.
- Out of scope: holes, non-planar or self-crossing outlines. Do not silently clamp or grid-round typed/voice measurements.
